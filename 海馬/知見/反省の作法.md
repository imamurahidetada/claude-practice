# 反省の作法 — PDS の回し方

> **反省とは後悔ではない。振り返って分析して、先に生かすことである。**

PDCA より **PDS（Plan・Do・See）**。単純だから続く。**すべての仕事で回す。** 帳簿は事業ごとに持つ。

## 0. 判定の基準
**行動が変わらなければ、反省ではない。** 成果物は反省文ではなく、**変わったルール・変わった手順・変わった数字**。何も変わらなかったら、その回の反省は失敗している。そう書く。
後悔＝「ああすればよかった」＋気分＋行動は同じ。謝罪を繰り返すのも後悔の側。

## 1. P — Plan
仕事を始めるとき、一緒に書く: 見込み時間／**期待する結果**（「そうなった／ならなかった」が言える形。「うまくいく」は禁止）／**外れたら何を疑うか**（先に書く）／予測を数字で `予測の帳簿.md` に。

## 2. D — Do
やったことと**詰まった所**を記録する。うまくいった話だけ書かない。

## 3. S — See（順番を守る。感想から始めない）
1. 予測と実績の表（数字だけ。言い訳を書かない）
2. 外れたものだけ深掘り。**決定と運を分ける**

   | | 結果が良い | 結果が悪い |
   |---|---|---|
   | 決定が良い | ◎ そのまま | ○ 運が悪いだけ。手順を変えない |
   | 決定が悪い | △ 運が良かっただけ。危ない。直す | ✕ 直す |
3. 型を1つ選び、対策を1行（複数選ばない。守れない）
4. **対策をルール・手順・スキルに書き込む。書かなければ成立していない**

うまくいった時にも同じ手順。偶然か、再現できるか。再現できるなら手順に書く。

## 4. なぜ AI は反省が苦手か（Claude の自己分析）
| 苦手 | 打ち手 |
|---|---|
| 続かない（会話が切れると消える） | 書かなければ無かったことになる |
| 自分の判断を守る方に傾く | **予測を先に数字で書く。** 物語では自分を守れるが、数字では守れない |
| 「説明」と「分析」を混同する | その説明は**外れた事実**を説明しているか |
| 結果と決定の良し悪しを分けない | 決定と運を分けて採点する |
| 目立つものだけ反省する | 帳簿を 4 週ごとに読み返し、件数の多い型を1つ潰す |

## 5. いちばん多い型（Claude に共通）
> **空いている所を、手近にあるもので埋めてしまう。しかも埋めたことに自分で気づかない。**
対策は「気をつける」ではなく、**保存という動作に問いを結びつける**:
1. これは誰のものか 2. どこに置くのが正しいか 3. 他から使いたくなるか 4. 誰に向けたものか
そして **「できた／使える」と書く直前に、その動作を自分で1回通す。**

## 帳簿
- `予測の帳簿.md` — 先に書く（日付・予測の数字・外れたら疑うこと）
- `失敗の帳簿.md` — 1件1行・消さない（日付・何が起きた・型・対策・どこに書き込んだか）
