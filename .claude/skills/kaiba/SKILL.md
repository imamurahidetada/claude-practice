# 海馬 — LLM Wiki の運用

場所: 憲法に書いた海馬の場所（A: 置き場の `海馬/`／B: `~/Documents/汎用/海馬/海馬/`。以下 `$V`）。**書くのは Claude、読むのは本人。** 面倒なのは書誌管理（相互参照と索引の更新）で、そこを Claude が引き受ける。

## 層
| 層 | 場所 | 誰が書くか |
|---|---|---|
| 元資料 | 本人が会話に貼った文・添付・メール | 不変。読むだけ。書き換えない |
| wiki | `$V/事業/`・`$V/知見/`・`$V/基盤/`・`$V/人物/`・`$V/` 直下（`本人.md`・`ゴール.md`・`保留中のタスク.md`） | Claude。どこに書くかは `$V/目録.md` の表 |
| index | `$V/目録.md`・各フォルダの索引 | Claude。毎回更新 |
| log | `$V/日々/` | Claude |
| sources | `$V/sources/` | Claude |
| 私事 | `$V/私事/` | 他へ書き写さない。共有時は外す |

## 操作1: ingest
1. 元資料を読む（`.docx` は Python の `python-docx`、`.pdf` は `pdftotext` か `pypdf`）。大きいものは目次・見出し・冒頭から
2. 要点を本人と話す。黙って書かない
3. `$V/sources/<資料名>.md` に要約（冒頭に出典・「他のノートへの影響」）
4. 関連する既存ノートを更新する。ここが本体。1つの資料が複数ページに波及するのが正常
5. `$V/目録.md` と該当の索引を更新。新しいノートには frontmatter（name・tags・updated）と関連リンク
6. 矛盾は消さずに両方残し、日付と出典を添えて「どちらが新しいか」を書く

## 操作2: query
1. 関連しそうなノートを探して読む（`grep` とファイル名から。目録 → 索引 → 本文）
2. **出典つきで答える**（「[[ノート名]] にこう書いてある」）
3. **海馬に無いことは「無い」と言う。** 推測で埋めない
4. 欠落は本人に伝えて ingest を提案

## 操作3: lint
順に調べ、見つけたものを報告してから直す: ①ページ間の矛盾 ②新しい事実に否定された古い記述（特に日付の入った方針） ③憲法（CLAUDE.md）の同じ腐り ④切れリンク ⑤孤立ページ ⑥あるべきなのに無いページ ⑦frontmatter の updated
```bash
python3 道具/リンク健診.py 海馬           # 孤立・切れ・大きさ
python3 道具/リンク健診.py 海馬 --quiet   # 数だけ・終了コード
# B の人は python3 ~/Documents/汎用/海馬/リンク健診.py ~/Documents/汎用/海馬/海馬（Windows は py -3）
```
grep でリンク切れを数えない。道具を使い、終了コードが 0 であることを見る。

## 操作4: 整理
**情報を減らさない。** 選択肢は ①移す ②索引を作る ③リンクを足す の三択。削除は入らない。重複して見えるものも、日付・文脈・読み手が違えば両方残す。ハブ ≤ 15KB・本文 ≤ 60KB を超えたら `経緯_YYYY-MM.md` へ移す。

## 日々の記録
その日に海馬へ足したものを `$V/日々/YYYY-MM-DD.md` に 1 行ずつ。無ければ作る。`日々/日々.md` の表にも 1 行。

## 保存
A: 書き終えたら `main` へ commit して push する（クラウドの作業場は会話の後に消える）。B: フックが同期する。急ぐときは `海馬の同期.sh now`。
