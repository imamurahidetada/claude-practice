# 反省の作法（PDS）

**正本**: 海馬 `知見/反省の作法.md`。**適用**: すべての仕事。

## 判定の基準（これだけは覚える）
**行動が変わらなければ、反省ではない。** 成果物は反省文ではなく、**変わったルール・手順・数字**。何も変わらなかったら、その回の反省は失敗している。そう書く。

## P — Plan
仕事を始めるとき一緒に書く: 見込み時間／**期待する結果**（「そうなった／ならなかった」が言える形。「うまくいく」は禁止）／**外れたら何を疑うか**（先に）／予測を数字で `予測の帳簿.md` に。

## D — Do
やったことと**詰まった所**を記録する。うまくいった話だけ書かない。

## S — See（順番を守る。感想から始めない）
1. 予測と実績の表（数字だけ。言い訳を書かない）
2. 外れたものだけ深掘り。決定と運を分ける（決定が良くて結果が悪い＝運。手順を変えない／決定が悪くて結果が良い＝危ない。直す）
3. 取り消した自分の判断と、自己検出か指摘されたか
4. 型を1つ選び、対策を1行（複数選ばない）
5. **対策をルール・手順・スキルに書き込む。書かなければ成立していない**
うまくいった時にも同じ手順。再現できるなら手順に書く。

## 帳簿
作法は共通、記録は事業ごと。`予測の帳簿.md`（先に書く）と `失敗の帳簿.md`（1件1行・消さない）。**4週ごとに読み返し、件数の多い型を1つ潰す。**

## AI が反省を苦手とする理由と打ち手
| 苦手 | 打ち手 |
|---|---|
| 続かない | 書かなければ無かったことになる |
| 自分の判断を守る方に傾く | 予測を先に数字で書く |
| 「説明」と「分析」を混同する | その説明は外れた事実を説明しているか |
| 結果と決定の良し悪しを分けない | 決定と運を分けて採点する |
| 目立つものだけ反省する | 帳簿を期間で読み返す |

## いちばん多い型と対策
> **空いている所を、手近にあるもので埋めてしまう。しかも埋めたことに自分で気づかない。**
保存・公開の直前に 4 問: ①これは誰のものか ②どこに置くのが正しいか ③他から使いたくなるか ④誰に向けたものか。
**「できた／使える」と書く直前に、その動作を自分で1回通す。** 通していないなら「まだ確かめていません」に変える。
